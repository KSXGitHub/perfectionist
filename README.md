# perfectionist

Additional linting rules for Rust projects.

`perfectionist` ships in two forms — pick whichever fits your project
better. Both run the same lint code; they only differ in how they hook
into your build.

## Usage — option A: standalone binary

A single command, no extra plugin infrastructure. Good for users who
just want to run perfectionist on a Rust project with one invocation.

Install:

```sh
# pre-built (fastest); requires `cargo binstall`
cargo binstall perfectionist

# or build from source against your local toolchain
cargo install perfectionist
```

Either path produces three executables in `~/.cargo/bin/`:
`perfectionist`, `cargo-perfectionist`, and `perfectionist-driver`.

Run the lints over the current project:

```sh
perfectionist
# equivalently:
cargo perfectionist
```

Pass extra flags through to the inner `cargo check` after `--`:

```sh
perfectionist -- --all-features -p my-crate
```

### How the binary finds its toolchain

`perfectionist`'s lints link against a specific nightly rustc (see
`rust-toolchain` in this repo). The launcher binary resolves a matching
sysroot at startup, in this order:

1. Its own per-user cache (`~/.cache/perfectionist/toolchains/...`).
2. A rustup-installed toolchain matching the pinned channel.
3. On-demand download from `https://static.rust-lang.org/dist/`.

The first time you run it on a fresh machine, expect a one-time
~150 MB download to the cache. Subsequent runs are instant. Pass
`--offline` to skip step 3 if you'd rather fail fast than fetch from
the network.

Override locations with environment variables:

| Variable                   | Purpose                                              |
| -------------------------- | ---------------------------------------------------- |
| `PERFECTIONIST_CACHE_DIR`  | Override the per-user cache root.                    |
| `PERFECTIONIST_TARGET_DIR` | Build-artifact dir (default: `target/perfectionist/<channel>/`). |
| `PERFECTIONIST_DRIVER`     | Path to the driver binary (development override).    |

### Pre-built binaries and verification

Each release publishes per-platform archives to the [Releases
page](https://github.com/KSXGitHub/perfectionist/releases). Every
archive carries a Sigstore-signed [SLSA build
provenance](https://slsa.dev/) attestation generated by GitHub
Actions, verifiable with `gh attestation verify`:

```sh
gh attestation verify perfectionist-<version>-<target>.tar.gz \
  --repo KSXGitHub/perfectionist
```

Supported targets: `x86_64-unknown-linux-gnu`,
`aarch64-unknown-linux-gnu`, `x86_64-apple-darwin`,
`aarch64-apple-darwin`, `x86_64-pc-windows-msvc`.

## Usage — option B: dylint plugin

Drop perfectionist into a project that already uses
[Dylint](https://github.com/trailofbits/dylint) for other lint
libraries.

Add `perfectionist` to your workspace's `dylint.toml`:

```toml
[workspace.metadata.dylint]
libraries = [
    { git = "https://github.com/KSXGitHub/perfectionist" },
]
```

Run the lints:

```sh
cargo dylint --all -- --all-targets
```

## Suppressing findings

Each lint registers under the `perfectionist` tool namespace, so a
suppression at a specific site looks the same regardless of which
usage option you picked:

```rust
#[expect(perfectionist::unicode_ellipsis_in_comments, reason = "3 ASCII dots would be incorrect here")]
```

## Configuration

Per-rule configuration is read from `dylint.toml` at the workspace
root. The configuration knobs for each rule are documented in that
rule's planning file. Once a rule is implemented, the same information
is reproduced in its module documentation.

```sh
just all
```
